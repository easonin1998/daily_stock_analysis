# Martin 持仓跟踪下一阶段备忘录

## 目标

把当前“信号日交易预案 + 单次持仓更新函数”接入实际持仓账本。用户只需在成交后确认一次真实成交信息，系统随后每天收盘后自动生成持有、收紧防守或下一开盘集合竞价卖出的条件单计划。

## 固定边界

- 只在日线收盘数据完整后决策，不依赖盘中分时和实时盯盘。
- 所有买卖信号均在收盘后形成，并在下一交易日开盘集合竞价执行。
- 券商条件单是执行工具，不假设能够保证触发价成交；跳空风险必须保留在提示和审计中。
- 不直接连接券商自动下单，除非未来单独完成授权、风控、幂等和审计设计。

## 状态模型

1. `pending_entry`：已发出买入信号，等待实际成交或取消。
2. `active`：已记录成交价、成交数量、成交日和初始防守价。
3. `exit_signaled`：收盘触发退出条件，等待下一开盘集合竞价卖出。
4. `closed`：已记录卖出成交并归档完整交易。
5. `cancelled`：买入未成交、价格越界或用户主动取消。

## 必需数据

- 信号与计划：策略版本、信号日、触发价、允许买入区间、初始防守价。
- 实际成交：账户、代码、成交日、成交价、数量、费用。
- 持仓路径：最高收盘价、持有交易日、EMA21、1R 是否激活、当前有效防守价。
- 审计信息：数据日期、行情来源、计划生成时间、通知状态和幂等键。

## 每日盘后任务

1. 校验 A 股交易日和最新完整日线，数据不新鲜时不生成新指令。
2. 读取 Martin 活跃持仓及真实成交价。
3. 更新最高收盘价、EMA21、收益率、持有日和有效防守价。
4. 依次检查初始防守、EMA21、最高收盘回撤 8%、1R 后成本防守、10 日跟随和 20 日上限。
5. 生成固定格式飞书卡片：今日动作、明日条件单、有效防守价、触发原因、持仓前提和跳空风险。
6. 使用“账户 + 股票 + 数据日 + 动作”去重，避免重复推送或重复记录退出信号。

## 交互与接入

- 优先复用现有 Portfolio 账户和交易流水，不新增平行持仓账本。
- Web 端增加“关联 Martin 计划”和“确认实际成交”入口；飞书交互作为后续便捷入口。
- 成交确认后调用 `rebase_martin_trade_plan_after_fill`，后续盘后调用 `update_martin_holding_plan`。
- 卖出成交后写回 Portfolio 流水，并保存计划价与实际成交价偏差供回测校准。

## 验收标准

- 同一成交只建立一个活跃计划，服务重启后状态不丢失。
- 实际成交价变化会正确重算 1R、2R、技术止损计仓风险、独立 ADR 跳空压力和成本防线；ADR 压力不直接压缩仓位。
- 盘后重复运行结果幂等；行情缺失、停牌、涨跌停和除权除息有明确状态。
- 飞书卡片与 API/Web 返回使用同一结构化计划，不由 LLM 临时生成价位。
- 单一通知失败不影响持仓状态落库，补发不会重复创建交易动作。
