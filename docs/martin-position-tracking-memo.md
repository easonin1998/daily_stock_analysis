# Martin 账户执行与持仓跟踪

## 能力边界

系统复用现有 Portfolio 账户、资金流水和成交账本，将 Martin 3.3 的选股结果换算成账户可执行计划。用户在 Web 端维护实际资金与成交后，后续选股和持仓计划会使用真实现金、持仓股数、批次成本、初始止损和 A 股 T+1 可卖数量。

- QMT 当前只提供只读行情、行业和题材数据，不读取真实持仓，也不提交订单。
- 所有策略动作由完整日线收盘数据计算，计划在下一交易日集合竞价执行。
- 飞书与 Web 消费同一份结构化计划；LLM 不负责临时编造股数、止损或卖出价。
- 券商条件单不能保证成交价。涨跌停、停牌、跳空和滑点仍需人工检查。

## Web 操作流程

1. 在 `/portfolio` 创建账户，并录入初始资金流水。
2. 在 `/screening` 选择该执行账户后运行 Martin 选股。
3. 查看候选的竞价区间、初始止损、建议股数、预计金额、仓位和风险热度；受市场状态或账户约束时页面会显示阻断原因。
4. 实际成交后回到 `/portfolio` 录入交易，勾选“关联 Martin 策略持仓”，选择首次试仓或盈利加仓，并填写该批次初始止损。可选填写选股 `run_id` 追溯信号。
5. 对升级前已经存在的持仓，在持仓表输入初始止损并点击“纳入策略”。系统以当前账户平均成本和股数建立基线，并从纳管日开始计算策略持有天数，不伪造历史批次。
6. 每日收盘后刷新持仓页，或在选股时继续选择同一账户。Web 与飞书会显示继续持有、可加仓、次日竞价减仓、次日竞价卖出或 T+1 暂不可卖。
7. 实际减仓或卖出后继续录入成交，并选择分批减仓或全部退出。下一次计算会按剩余批次、费用后平均成本和剩余风险重建组合 R。

自动任务调用选股接口时也必须传入 `account_id`，才能生成账户相关的股数和持仓动作；未关联账户时仍只输出通用候选计划。

执行账户必须与选股市场和策略 `market_scope` 一致。当前 Martin 3.3 只支持 A 股，因此 Web 只列出 A 股账户，后端也会拒绝用港股或美股账户进行人民币计仓。

## 账户计仓

候选使用下一开盘的最高允许竞价价作为保守计仓价格。A 股股数向下取整为 100 股整数手，并按以下约束共同取最小值：

- 可用现金；
- 当前市场状态允许的目标总仓位剩余额度；
- Martin 3.3 初始试仓上限；
- 市场状态调节后的单只仓位上限；
- `账户权益 × 单笔风险比例 ÷ (计仓价 - 初始止损价)`；
- `账户权益 × 组合热度上限 - 已管理持仓的初始技术风险`；
- 最多持仓数量的剩余名额。

取整后的名义仓位若仍低于当前市场状态下的最小有效仓位，则整笔阻断，不用一手小仓位制造无意义交易；这也是账户权益提高后不会机械地仍只买 100 股的约束。

多个候选按结果顺序依次占用现金、目标仓位、风险热度和持仓名额，后面的候选不会重复使用前面已经预留的预算。市场状态使用筛选引擎的统一规则：强势进攻、正常进攻、中性防守和风险关闭分别调节目标仓位、最多持仓、单笔风险、组合热度与单只上限；`risk_off` 不允许新开仓或加仓。

盈利加仓只对已经纳入策略、状态仍为持有且达到下一 R 门槛的持仓开放。加仓数量同时受现金、目标总仓位、单只上限、单次加仓权重、单笔风险和组合热度约束，不向亏损持仓摊低成本。加仓同样使用“收盘决策、下一交易日集合竞价执行”，按 ADR20 自适应竞价区间的最高允许价保守计算股数、名义金额和新增风险；超出区间则不成交。选股流程直接传入当日市场状态；单独打开持仓页时读取本地已持久化的最近市场状态，且历史日期不会读取未来状态，避免绕过风险关闭限制。

## 持仓状态

每笔策略成交可记录：

- `strategy`、`strategy_version`；
- `signal_run_id`；
- `strategy_action`：首次试仓、盈利加仓、分批减仓或全部退出；
- 买入批次的 `initial_stop_price`。

系统为每个“账户 + 股票 + 市场 + 策略”保存持仓动态状态，包括批次剩余股数、费用后成本、保护价、风险、最高收盘、组合峰值 R、EMA9 连续失守天数和减仓次数。状态日期跟随最新完整日线，而不是请求发生的自然日期；盘前、周末重复刷新同一根 K 线不会重复累计 EMA9 天数。加仓后只有在该成交日的完整收盘数据可用时才重建组合峰值 R，不用集合竞价成交价或上一交易日收盘提前激活利润保护。尚未等到匹配收盘时显示“等待当日收盘”，但该批次初始风险仍计入组合热度。

旧持仓只有在用户提供有效初始止损后才会纳入管理。未纳管持仓仍计入账户市值、现金和持仓名额，但因缺少可审计的初始风险，不计入策略风险热度，也不会自动生成卖出价。

## 退出与 T+1

持仓计划直接复用 Martin 3.3 的 `update_martin_holding_plan`，按剩余批次的费用后成本和技术风险计算当前 R、利润底线、波动回撤、EMA9/EMA21、衰竭减仓与最终退出。

- 快照同时保留“当日实际可卖股数”和“下一竞价预计可卖股数”。当日新买入的 A 股当天仍不可卖，后端也会拒绝同日卖出；但盘后生成的退出指令在下一交易日开盘竞价执行，因此按届时已满足 T+1 的预计可卖数量生成条件单。
- 分批减仓向下取整为 100 股整数手。目标不足一手时继续持有并于下一交易日重评，不会把 20 股目标错误放大为卖出 100 股。
- 港股、美股等市场不套用 A 股 T+1 限制。
- 删除或更正历史成交会清除该股票已派生的策略状态；修正账本后需要重新刷新计划，旧持仓必要时重新纳入策略。

## API

| 接口 | 用途 |
| --- | --- |
| `POST /api/v1/portfolio/trades` | 记录实际成交和可选策略来源、动作、初始止损、选股运行 ID |
| `GET /api/v1/portfolio/strategy-plan?account_id=<id>` | 生成指定账户的盘后持仓动作 |
| `POST /api/v1/portfolio/positions/{symbol}/strategy` | 为旧持仓设置初始止损并纳入 Martin 管理 |
| `POST /api/v1/screening/screen` | 传 `account_id` 后生成账户约束的候选股数和飞书持仓计划 |
| `POST /api/v1/screening/screen/tasks` | 后台任务版本，字段语义相同 |

## 数据与降级

- 持仓退出优先读取数据库 `StockDaily` 的本地日线，缺失时回退到本地日线特征库。
- 缺少最新收盘、少于 21 根完整日线，或最近日线距计划日超过 14 个自然日时，状态为 `data_insufficient`，保留旧条件并要求人工确认，不用短样本或明显陈旧的 EMA21 自动改变持仓。
- 策略管理持仓与账户实际股数不一致时状态为 `tracking_mismatch`，不猜测缺失成交。
- 未关联账户的选股、单一通知渠道失败或策略计划不可用，不应破坏基础选股结果与持仓账本。

## 回滚

代码回滚不会删除新增的可空成交来源字段和 `portfolio_strategy_positions` 状态表，也不会影响原有 Portfolio 成交、资金和公司行动账本。若只需停止账户策略联动，选股请求不传 `account_id`，并继续把成交作为普通手工交易录入即可。
